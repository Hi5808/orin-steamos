# Building orin-steamos (x86_64 Linux host)

`build.sh` downloads NVIDIA's public Jetson Linux r39.2.1 BSP and sample rootfs, customizes the rootfs in a qemu-aarch64 chroot, and leaves a flash-ready `work/Linux_for_Tegra`. It never touches a Jetson; flashing is `sudo ./flash.sh` ([FLASH.md](FLASH.md)).

## 1. Host prerequisites
- x86_64 Linux with sudo and internet access (about 3.1 GB from NVIDIA, about 140 MB of Linux kernel source from kernel.org, Ubuntu ports packages inside the chroot, and about 105 MB from Valve with `PREINSTALL_STEAM=1`).
- **Disk:** about **16 GB free** in the repo directory (`MIN_FREE_GB`; measured: downloads 3.1 GB plus work tree 8.8 GB). Flashing generates images inside `work/` (several GB more). `./build.sh release` needs about 4 GB more. After a successful build `sudo rm -rf downloads` frees 3.1 GB.
- **Packages:**
  - Ubuntu ≤ 24.04: `sudo apt install qemu-user-static binfmt-support zstd lbzip2 xz-utils curl openssl python3`
  - Ubuntu ≥ 25.04 / Debian 13: `sudo apt install qemu-user qemu-user-binfmt binfmt-support zstd lbzip2 xz-utils curl openssl python3` (`qemu-user` provides `/usr/bin/qemu-aarch64-static`, the path NVIDIA's scripts require).
  - Optional, for extra checks in `validate`: `shellcheck nodejs desktop-file-utils`.
  - For flashing: `docker.io` (or Docker CE), `nfs-kernel-server`.
- Check: `ls -l /usr/bin/qemu-aarch64-static && cat /proc/sys/fs/binfmt_misc/qemu-aarch64` (should say `enabled` and include the `F` flag).

## 2. SSH key
The image allows SSH **only with a key**. Nothing is hardcoded: the build installs the public key(s) from
- `SSH_AUTHORIZED_KEYS=/path/to/keys.pub` (a file, one or more keys), or by default
- `~/.ssh/id_ed25519.pub` of the user who ran `sudo`.

No key found means the build stops, unless you set `ALLOW_NO_SSH_KEY=1` (console login only).

## 3. Build
```bash
sudo ./build.sh                    # fetch, extract, binaries, customize, modules, user, steam, tune, validate
sudo ./build.sh release            # same + output/orin-steamos-L4T-r39.2.1.tar.zst (private: see below)
sudo PREINSTALL_STEAM=0 ./build.sh # no Valve files in the image
sudo SSH_AUTHORIZED_KEYS=$HOME/.ssh/other.pub ./build.sh
```
- Stages can be re-run one at a time: `sudo ./build.sh customize`, `sudo ./build.sh validate`, and so on.
- All settings are in `config.env` and can be overridden from the environment as above.
- **Runtime** (x86_64, qemu 10): about 20–40 min plus downloads (extract + apply_binaries ~5 min, chroot customize ~7 min, modules ~1–2 min, the rest ~2 min).
- **Success:** `validate: N passed, 0 failed`, then `==> done`.

| Stage | What it does |
|---|---|
| fetch | NVIDIA BSP + sample rootfs; sha1 (NVIDIA's list) and sha256 (pinned in config.env) checks |
| extract / binaries | unpack, NVIDIA `apply_binaries.sh` |
| customize | apt packages (SDDM, openbox, XFCE, zenity, earlyoom, zram, …), Tailscale (installed only), image cleanups, rootfs overlay, services |
| modules | builds `uinput`, `hid-steam`, `hid-playstation`, `hid-nintendo`, `hid-sony` from upstream linux-6.8.12 sources against the image's kernel headers |
| user | user `steamos`, random sudo password to `output/SECRETS.txt` (0600), SSH key(s) |
| steam | `PREINSTALL_STEAM=1`: Valve's ARM64 client bootstrap into `/home/steamos/.local/share/Steam` |
| tune | quiet boot in extlinux |
| validate | offline checks of the rootfs (packages, services, sshd, polkit, sessions, OOM policy, modules, …) |

## 4. Outputs (all gitignored)
- `work/Linux_for_Tegra/`: the flash-ready tree. `sudo ./flash.sh` uses it.
- `output/SECRETS.txt`: the steamos sudo password generated by *your* build (never printed; the build log redacts it).
- `output/*.tar.zst` (`release` only): contains NVIDIA's BSP, your SSH public key, your password hash and, with `PREINSTALL_STEAM=1`, Valve's client. **Keep it private.** See README "Licensing" before publishing any image.

## 5. Does the build need a container?
Probably not. `apply_binaries.sh` and `l4t_create_default_user.sh` (r39.2.1) don't check the host Ubuntu version; they need `/usr/bin/qemu-aarch64-static` and a working aarch64 binfmt (built natively on Ubuntu 26.04 with qemu 10.2). Only **flashing** needs Ubuntu 22.04, which `flash.sh` handles with a container. If a native build fails in apply_binaries or create_user, run it in a 22.04 container:
```bash
sudo docker run --rm -it --privileged \
  -e HOST_QEMU_VERSION="$(qemu-aarch64-static --version | awk '/version/{print $3; exit}')" \
  -e SSH_AUTHORIZED_KEYS=/build/authorized_keys.pub \
  -v "$PWD:/build" -w /build ubuntu:22.04 bash -c \
  'apt-get update && apt-get install -y qemu-user-static binfmt-support zstd lbzip2 xz-utils curl openssl python3 sudo ca-certificates && ./build.sh'
```
(copy your public key to `./authorized_keys.pub` first; `*.pub` is gitignored.)
